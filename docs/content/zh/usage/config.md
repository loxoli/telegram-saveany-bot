# 檔案命名與重名策略

SaveAny-Bot 支援在 Telegram 中透過 `/config` 和 `/fnametmpl` 命令自訂儲存檔案的命名方式, 以及處理與已存在檔案重名時的衝突策略.

## `/config` — 使用者設定

`/config` 命令會彈出一個內嵌選單, 您可以在其中修改以下兩項使用者層級設定:

- **檔案名稱策略** — 儲存檔案的命名方式
- **重名檔案儲存策略** — 目標儲存中已存在同名檔案時的處理方式

設定按使用者分別儲存, 對該使用者後續所有的儲存/轉存任務生效.

### 檔案名稱策略

| 選項 | 行為 |
|---|---|
| `預設` | 使用媒體原始檔案名稱, 沒有原始檔案名稱時使用生成名稱 |
| `優先從訊息生成` | 優先根據訊息內容 (如 caption、文字) 生成檔案名稱, 而非原始檔案名稱 |
| `自訂範本` | 使用 `/fnametmpl` 設定的自訂範本渲染檔案名稱 |

### 重名檔案儲存策略

| 選項 | 行為 |
|---|---|
| `始終重新命名` (預設) | 保留已有檔案, 將新檔案以另一個名稱儲存 |
| `每次詢問` | 每次遇到重名時透過內嵌按鈕提示您選擇 |
| `始終覆蓋` | 用新檔案取代已有檔案 |
| `始終略過` | 對重名檔案不做處理 |

{{< hint info >}}
重名策略僅在能夠偵測檔案是否已存在的儲存後端生效. 不支援偵測檔案是否存在的儲存後端會退化為覆蓋行為.
{{< /hint >}}

{{< hint warning >}}
**重名策略目前僅套用於 Telegram 檔案 (直接傳送給 Bot 的媒體/文件).**

透過解析器下載的內容 (如 Twitter / X 等網站連結)、直接連結、yt-dlp、aria2 等任務**不受重名策略影響**, 一律採用「始終重新命名」行為: 遇到同名檔案時自動以 `檔名_1.副檔名`、`檔名_2.副檔名` ... 的方式遞增命名, 不會覆蓋、略過或詢問.

因此即使您將重名策略設為 `始終覆蓋` 或 `始終略過`, 這些來源的下載仍只會自動改名.
{{< /hint >}}

## `/fnametmpl` — 自訂檔案名稱範本

當檔案名稱策略設定為 `自訂範本` 時, SaveAny-Bot 會用 `/fnametmpl` 設定的範本來渲染所儲存檔案的檔案名稱.

```
/fnametmpl [範本]
```

- 不帶參數執行 `/fnametmpl` 會顯示當前範本以及說明
- 帶範本字串執行則會將其設為您的檔案名稱範本

範本使用 Go [`text/template`](https://pkg.go.dev/text/template) 語法. 可用變數如下:

| 變數 | 說明 |
|---|---|
| `{{.msgid}}` | Telegram 訊息 ID |
| `{{.msgtags}}` | 訊息中的標籤, 以 `_` 連接輸出 |
| `{{.msggen}}` | 根據訊息生成的檔案名稱 |
| `{{.msgdate}}` | 訊息日期, 格式 `YYYY-MM-DD_HH-MM-SS` |
| `{{.msgraw}}` | 訊息的原始文字內容 (不做處理) |
| `{{.origname}}` | 媒體的原始檔案名稱 (如有) |
| `{{.chatid}}` | 訊息所在聊天室的 ID |

範例:

```
# 固定前綴 + 訊息 ID + 日期
/fnametmpl 圖片_{{.msgid}}_{{.msgdate}}.jpg

# 優先使用原始檔案名稱, 沒有則用生成名稱
/fnametmpl {{.origname}}
```

{{< hint warning >}}
範本僅在檔案名稱策略設定為 `自訂範本` 時生效. 如果範本解析失敗, SaveAny-Bot 會退回到預設的檔案名稱生成邏輯.
{{< /hint >}}
